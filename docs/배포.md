# 배포

교실 PC — 쿨메신저 말고는 아무것도 없는 PC — 에 **설치 파일 하나로** 들어가는 것이 목표다.
파이썬·Node·pip 를 교사가 손댈 일이 없어야 한다.

## 배포 기준 커밋

`origin/main` 을 그대로 쓴다. 구글 캘린더 연동은 **이미 main 에 들어와 있다**:

| | |
| --- | --- |
| 기준 | `origin/main` |
| 구글 캘린더 병합 | `83077a2` (PR #15) — main 의 조상 |
| 그 뒤 후속 수정 | `dfc76b1` 브라우저 못 열던 것, `455f55b` 단추 크기 |
| 릴리스 브랜치 | `release/v0.1.0` = main + 아래 세 커밋 |

`release/v0.1.0` 에만 있는 것:

1. `ci:` embeddable CPython 번들 (`ci/windows-nsis` 에서 가져옴 — main 에 없던 유일한 브랜치)
2. `fix(automator):` 날짜 칸 확인을 ↑ 대신 Backspace 로
3. `feat(widget):` 설치본에서 로컬 AI 가 Ollama 를 직접 호출

> `origin/ci/windows-nsis` 는 main 보다 23 커밋 뒤처져 있었다. 브랜치째 병합하지 않고
> 필요한 한 커밋만 옮겨 왔다. 그 커밋의 `main.rs` 수정은 지금 main 의 「콘솔 창 숨기기」와
> 같은 자리를 건드려 충돌했고, 둘 다 살리는 쪽으로 손으로 합쳤다.

없을 때 규칙 엔진 결과까지 같이 날려 버리지 않는다.

## 메운 구멍 둘

### 1. 설치본 안에서 로컬 AI 가 Ollama 를 직접 부른다

설치본에는 Node 서버가 없다. 로컬 AI 는 그 서버가 비식별하고 Ollama 를 부르는
구조라, 설치해서 쓰면 로컬 AI 가 아예 돌지 않았다.

- 비식별이 위젯으로 왔다 — `apps/…/src/services/piiRedact.js`.
  규칙·정규식·토큰 이름은 서버(`server/src/redact.ts`)와 **같다.** 갈라지면
  「서버로 볼 때와 설치본으로 볼 때 가려지는 것이 다르다」가 된다.
  다른 점 하나: 위젯은 원문을 **어디에도 저장하지 않는다.** 되돌릴 일이 없다.
- HTTP 는 셸(Rust `ollama_chat`/`ollama_tags`)이 친다. 웹뷰에서 곧장 `fetch` 하면
  Ollama 가 `Origin` 을 보고 막아(설치본 origin 은 `http://tauri.localhost`),
  교사가 `OLLAMA_ORIGINS` 를 손대야만 도는 프로그램이 된다.
- 주소는 `localhost`·`127.0.0.1` 만 받는다. 가렸다 해도 쪽지 텍스트가 이 PC 밖으로
  나가는 길은 만들지 않는다. 프록시도 타지 않는다(`no_proxy`).

### 2. 파이썬 인터프리터·opencv 를 교사가 pip 안 해도 되게

`scripts/prepare-windows-python.ps1` 이 빌드 때 Windows embeddable CPython 3.12 와
`pillow`·`numpy`·`opencv-python` 을 `src-tauri/resources/python-runtime/` 에 채우고,
Tauri 가 그것을 `python/` 리소스로 함께 설치한다.

셸은 설치본이면 같이 넣은 `python.exe` 를, 개발 중이면 예전처럼 `py -3` 을 쓴다
(`python_launch()` in `main.rs`).

바이너리는 커밋하지 않는다 — `.gitignore` 가 막고, CI 가 매번 새로 채운다.

## 릴리스 내는 법

`gh` 없이도 된다. 태그를 밀면 CI 가 만들어 올린다.

```bash
git push origin release/v0.1.0
```

```bash
git tag -a v0.1.0 -m "쿨린 일정 위젯 v0.1.0" && git push origin v0.1.0
```

`.github/workflows/release-windows.yml` 이 도는 순서:

1. schedule-engine 빌드·시험 → 위젯 시험 (깨지면 여기서 멈춘다)
2. `prepare-windows-python.ps1` — CPython + 휠 번들
3. `tauri build --bundles nsis`
4. `check-bundle-clean.ps1` — **설치본에 개인정보·목업 바이너리가 섞였는지 확인**
5. artifact 업로드 → (태그일 때만) GitHub Release 에 exe 와 `docs/설치순서.md`

손으로 한 번 돌려 보려면 Actions 에서 `workflow_dispatch`. 태그가 아니면 Release 는
만들지 않고 artifact 만 남는다.

## 넣지 않는 것

| | 왜 |
| --- | --- |
| Ollama 와 모델 | 용량(수 GB)과 라이선스. 쓰는 사람이 따로 깐다 |
| `CoolMessenger.exe` (목업) | 저장소에서 gitignore. 데모 키트로 따로 나눠 준다 |
| 실제 쪽지 `xls`, `coolexcel/` | 학생·교사 실명이 들어 있다 (PRD 22장) |
| `pii.key` · `pii-map.json` | 이 PC 의 로컬 열쇠와 암호문 |

4단계의 `check-bundle-clean.ps1` 이 이 넷을 빌드 뒤에 다시 확인한다. 한 번 나가면
되돌릴 수 없는 종류의 실수이기 때문이다.

## 심사 스모크

설치 직후의 PC 에서 위에서 아래로. **Ollama 없이 6번까지 전부 통과해야 한다.**

| # | 하는 일 | 통과 기준 |
| --- | --- | --- |
| 1 | 쿨메신저를 켜고 로그인 | 메신저 창이 떠 있다 |
| 2 | 위젯 **[가져오기]** | 위젯이 잠깐 숨었다 돌아오고, 오류 없이 끝난다 |
| 3 | 일정 탭 | 캘린더에 일정이 채워져 있다. 검토 탭에도 항목이 있다 |
| 4 | 자동 정리 시각 | 예약한 시각이 화면에 그대로 있다 |
| 5 | 날짜 칸에 `20260828` `20260829` → [기간 정리] | 그 기간 쪽지만 들어온다. 기간이 어긋나면 **쓰지 않고 멈춘다** |
| 6 | 일정의 **[구글 캘린더]** | 기본 브라우저에 등록 화면이 열린다 |
| 7 | (Ollama 있으면) 쪽지 요약 | 3줄 요약이 나온다. 없으면 내장 문안이 나오고 실패하지 않는다 |

5번이 이 프로그램의 핵심 안전장치다. 기간이 조용히 틀어진 채 «성공»하는 것이 가장
나쁜 결과라(기술계획서 8.4), 날짜 칸에 값이 들어갔는지 화면으로 확인하고, 내려받은
표의 날짜가 요청한 기간 안인지 `ingest.py` 가 한 번 더 본다.

## 데모 키트

메신저가 없는 PC 에서도 보여 줄 수 있게 한 벌로 묶는다.

```bash
node scripts/make-seed-xls.mjs
```

`packages/schedule-engine/fixtures/golden.json` 의 **합성** 쪽지로 바탕화면에
`coolmsg_*.xls` 를 만든다. 실제 데이터는 쓰지 않는다 — golden set 자체가
「실제 원문은 쓰지 않는다」는 전제로 만든 것이다. 그 파일이 있으면 메신저 없이도
위젯이 일정을 보여 준다.

나눠 줄 묶음: `쿨린위젯_설치.exe` + `docs/설치순서.md` + (목업이 필요하면)
`CoolMessenger.exe`·`설치.bat`·`사용설명.txt` + 씨앗 `xls`.
