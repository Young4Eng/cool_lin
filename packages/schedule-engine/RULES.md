# 쪽지에서 할 일을 뽑는 규칙

쪽지 한 건에서 캘린더에 넣을 업무를 어떻게 뽑는지 정리한 문서다.
규칙은 짐작이 아니라 **실제 쪽지 3,236건(중복 제거 후)을 세어 나온 빈도**에서 만들었다.
숫자를 다시 뽑으려면 `npm run analyze`.

연동 방법과 JSON 계약은 [README.md](./README.md), 평가 기준은 [EVALUATION.md](./EVALUATION.md)에 있다.

---

## 1. 캘린더 한 줄에 들어가는 네 가지

| | 무엇을 보는가 |
|---|---|
| **① 언제** | 날짜·시각·교시. 기준은 **쪽지를 받은 날** |
| **② 무엇을** | 내가 할 행동(제출·신청)이거나 학교가 치르는 행사(회의·연수) |
| **③ 누가** | 전 교직원·담임·N학년. 내 역할과 맞는지 |
| **④ 어디서** | 강당·체육관·연구실 같은 장소 |

**「언제」가 없으면 나머지가 아무리 그럴듯해도 일정으로 만들지 않는다.**
실제 쪽지의 57.7%가 여기서 걸러진다.

---

## 2. 3,388줄이 15건이 되기까지

실제 파일 7개, 기준일 2026-08-28, 가져오기 기간 14일:

```
읽은 행                3,388
  기간 밖 (14일 초과)  −3,088
  중복 쪽지              −140
  인용문만 있음            −7
  민감정보 격리            −1
  일정 날짜가 지남       −149
  날짜·행동 없음         −139
─────────────────────────────
  일정 후보                15   (자동등록 가능 3)
```

**가장 큰 몫은 「쪽지는 최근인데 그 안의 날짜가 지났다」(149건)이다.**
8월 20일에 열린 협의회 결과를 8월 27일에 공유하는 쪽지가 전형적인 예다.
후보가 적다고 파서를 의심하기 전에 이 숫자를 먼저 본다.

## 3. 처리 순서

순서를 바꾸면 안 된다. 각 단계가 앞 단계 결과에 기댄다.

1. **인용문 떼어내기** — `홍길동님이 보낸글 >>` 이후는 이전 대화다. 인용문만 남으면 후보를 만들지 않는다.
2. **중복 쪽지 걸러내기** — 방향·상대·발송시각·본문으로 지문을 만들어 한 번만 센다.
3. **민감정보 찾아 가리기** — 주민번호·계좌·비밀번호 값·상담 내용이 보이면 격리한다.
   **중복 제거보다 뒤에 둔다.** 먼저 가리면 서로 다른 두 쪽지가 같은 placeholder로 바뀌어
   같은 지문이 되고 하나로 합쳐진다.
4. **문장으로 나누기** — 쪽지 하나를 한 덩어리로 보지 않는다.
5. **날짜·시각·교시 뽑기** — 하나도 없으면 그 문장은 여기서 끝이다.
6. **무엇을·누가·어디서 읽고 점수 매기기**
7. **제목 만들고 확인 표시 붙이기**

한 단계씩 눈으로 확인하려면 `npm run trace`.

## 4. ① 언제 — 기준은 언제나 「쪽지를 받은 날」

「모레까지」라고 적힌 같은 문장이라도 8월 27일에 받았으면 8월 29일이고,
8월 31일에 받았으면 9월 2일이다.

기준일이 **2026-08-27(목)** 일 때:

| 본문에 적힌 말 | 어떻게 읽는가 | 결과 | 확인 표시 |
|---|---|---|---|
| `8월 28일` · `8/28` · `2026-08-28` · `9.2.` | 적힌 그대로 | `2026-08-28` | — |
| `오늘` · `금일` | 받은 날 | `2026-08-27` | — |
| `내일` · `명일` | 받은 날 +1 | `2026-08-28` | — |
| `모레` | 받은 날 +2 | `2026-08-29` | — |
| `글피` | 받은 날 +3 | `2026-08-30` | — |
| **`금요일까지`** | **받은 날 이후 가장 가까운 금요일** | `2026-08-28` | `요일만 적힘` |
| `화요일 창체` | 받은 날이 목요일이라 다음 주로 | `2026-09-01` | `요일만 적힘` |
| `다음 주 월요일` | 받은 날이 속한 주의 다음 주 | `2026-08-31` | — |
| `8월 27일(목)` | 날짜를 쓰고 요일은 검사만 | `2026-08-27` | — |
| `9월 4일(목)` — 실제로는 금요일 | 날짜는 쓰되 자동등록은 막음 | `2026-09-04` | `날짜·요일 불일치` |
| `1월 5일` — 8월에 받음 | 학사연도가 넘어간 것으로 보고 다음 해 | `2027-01-05` | `연도 생략` |
| `5~6교시` | 교시 번호를 보존. 시각으로 바꾸지 않음 | 교시 5–6 | `교시표 미설정` |
| `오후 3시 30분` | 정확한 시각 | `15:30` | — |
| `3시에` — 오전·오후 없음 | 학교 일과 기준 오후로 보되 확정하지 않음 | `15:00` | `오전·오후 불명확` |
| `8/11~8/13` | 시작일과 종료일 | `08-11 → 08-13` | — |

### 「요일만 적힘」을 공들여 다루는 이유

실제 쪽지에서 **요일만 적힌 표현이 6.9%, 「모레」는 0.1%**다. 70배 차이다.
「금요일까지 제출」이 학교에서 가장 흔한 마감 표현이라, 이걸 놓치면 진짜 업무가 통째로 사라진다.
대신 어느 주의 금요일인지 확신할 수 없으므로 표시를 붙여 사람이 한 번 보게 한다.

### 날짜처럼 생겼지만 날짜가 아닌 것

`010-9094-8756`(전화번호), `내선 114`, `10514`(학번), `15:20`의 15 — 전부 막아 두었다.
시각 구간을 먼저 확보한 뒤 날짜를 찾는 순서라 `15:20`이 8월 15일이 되지 않는다.

## 5. ② 무엇을 — 「내가 할 일」과 「학교가 치르는 일」

이 구분이 캘린더에서 **할 일**로 갈지 **일정**으로 갈지를 정한다.
괄호 안은 실제 쪽지에서 그 말이 나온 비율이다.

| 무엇을 찾는가 | 찾는 말 | 결과 |
|---|---|---|
| **내 행동** | 제출 (6.4%) · 신청 (6.8%) · 입력 (5.4%) · 작성 (5.5%) · 회신 (5.4%) · 배부 (3.6%) · 취합 · 참석 | 할 일 후보 |
| **기한 표현** | 까지 (14.4%) · 마감 (2.4%) · 기한 (0.9%) | 내 행동과 함께면 **마감** |
| **학교 행사** | 회의 (3.9%) · 연수 (4.2%) · 고사 (3.8%) · 협의회 (2.8%) · 점검 (2.9%) · 상담 (1.8%) · 체험학습 (1.7%) · 검진 · 훈련 · 공개수업 | 일정 후보 |
| **치른다는 서술어** | 실시합니다 · 진행합니다 · 개최합니다 · 운영합니다 | 행사 이름이 사전에 없어도 일정으로 인정 |

### 일부러 신호로 쓰지 않는 말

**「부탁드립니다」 23.4%, 「감사합니다」 30.2%.**
너무 흔해서 공식 공지 끝에도, 잡담 끝에도 똑같이 붙는다.
있다는 것만으로는 아무것도 알려주지 않으므로 단독 신호로 쓰지 않는다.

## 6. ③ 누가 · ④ 어디서

| 찾는 것 | 예 | 쓰임 |
|---|---|---|
| **전 교직원·필수** | 전 교직원 · 모든 선생님 · 반드시 · 필수 (7.0%) | 가장 높은 관련도. 자동등록 대상 |
| **담임** (13.5%) | 담임 선생님께서는 | 내가 담임이면 관련 있음 |
| **학년** (22.7%) | 2학년 · 1·2학년 | 내 담당 학년과 겹치면 관련 있음 |
| **장소** | 강당 · 체육관 · 시청각실 · 2학년 연구실 · 302호 | 캘린더 장소 칸 |

역할 태그를 비워 두면 대부분 걸러진다. **이건 고장이 아니라 설계된 동작이다.**
이름·학교명·연락처는 묻지 않는다.

## 7. 제목 만들기

쿨메신저의 `제목` 열은 **대개 본문 첫 줄이 잘린 값**이다.
실제 데이터에서 71.2%가 본문 첫 부분과 같았고, 87.5%가 24자 이상으로 잘려 있었으며,
22.2%는 인사말로 시작했다. 그대로 쓰면 캘린더에
`안녕하세요 담임선생님, 교무부 최은지입니다. 학급함에` 가 박힌다.

순서대로 시도한다.

1. 제목 열이 진짜 제목처럼 보이면 그대로 쓴다 (짧고, 인사말이 아니고, 본문 앞부분이 아니고, 문장이 아닐 것)
2. 행사 이름이 잡혔으면 앞 수식어까지 살린다 → `2학기 교무회의`, `1학년 건강검진`
3. 아니면 「무엇을 + 무엇 한다」를 뽑는다 → `출석부 제출`
4. 그것도 없으면 분류 이름을 쓴다 → `제출 마감`

목적어를 찾을 때 행동 **바로 앞** 어절부터 거꾸로 최대 4개만 본다.
문장 앞쪽까지 끌어오면 `부를 금요일 점심 전까지 체육관 앞 제출` 같은 제목이 나온다.
접속사(`그리고`)와 날짜 조각(`금요일`, `점심`)은 만나는 즉시 끊는다.

## 8. 실제 추출 예시

기준일 2026-08-27(목). 아래 예문은 실제 쪽지가 아니라 같은 표현 구조로 새로 쓴 합성 예문이다.

### 그대로 등록되는 것

```
문장   8월 28일(금) 15:20 강당에서 2학기 교무회의가 있습니다. 전 교직원 참석 부탁드립니다.
─────────────────────────────────────────────────────────────
언제   2026-08-28 15:20        무엇을  회의
누가   전 교직원                어디서  강당
제목   2학기 교무회의           분류    공식 일정 · 신뢰도 높음(0.96)
결과   자동등록
```

### 확인이 필요한 것

```
문장   8월분 스포츠클럽 출석부를 금요일까지 제출해 주세요.
─────────────────────────────────────────────────────────────
마감   2026-08-28              무엇을  제출
제목   출석부 제출              분류    마감 · 신뢰도 검토 필요(0.64)
결과   ⚠ 요일만 적힘 — 이번 주 금요일이 맞는지 사람이 확인해야 등록
```

```
문장   내일 5~6교시 계기교육을 실시합니다.
─────────────────────────────────────────────────────────────
언제   2026-08-28 · 5–6교시     시각    비움
분류   공식 일정 · 검토 필요
결과   ⚠ 교시표 미설정 — 5교시가 몇 시인지는 학교마다 달라 추측하지 않는다
```

### 버리는 것

```
문장   감사합니다. 내일도 좋은 하루 보내세요.
─────────────────────────────────────────────────────────────
언제   2026-08-28  (찾긴 함)    무엇을  없음
결과   후보 만들지 않음 — 날짜가 있다는 이유만으로 일정으로 만들지 않는다
```

```
문장   8월 20일 진행된 협의회 결과를 공유합니다.
─────────────────────────────────────────────────────────────
언제   2026-08-20              무엇을  협의회
결과   후보 만들지 않음 — 일정 날짜가 이미 지났다 (실제 데이터에서 149건)
```

## 9. 캘린더에 올리지 않는 쪽지

- **인사·감사·단순 확인** — 「감사합니다」, 「네~」, 「좋은 주말 보내세요」. 날짜가 섞여 있어도 뺀다.
- **남의 개인 일정** — 「저는 8월 31일 개인 출장입니다」. 나에게 할 일이 없다.
- **이미 지난 일정** — 통계에는 남기지만 후보함에는 넣지 않는다.
- **민감정보가 있는 쪽지** — 주민번호·계좌·비밀번호 값·상담/건강 내용. 후보 자체를 만들지 않는다.
- **인용문만 있는 답장** — 이번에 새로 쓴 내용이 없다.
- **긴급 공지** — 「오늘 폭염으로 단축 수업」 같은 당일 공지는 캘린더보다 알림에 가깝다.

## 10. 바로 등록할 것과 물어볼 것

아래를 **모두** 만족해야 사용자에게 묻지 않고 캘린더에 넣는다.
하나라도 걸리면 후보함에 남겨 확인을 받는다.

- 날짜가 오늘이거나 미래일 것
- 공식 일정이거나 내 마감·할 일일 것
- 희망자·신청자 대상 표현이 없을 것
- 민감정보가 없을 것
- **확인 표시가 하나도 없을 것** — `요일만 적힘` · `날짜·요일 불일치` · `연도 생략` ·
  `오전·오후 불명확` · `교시표 미설정` · `종료일 불명확` · `반복 주기 불명확` · `날짜 범위 벗어남`
- 변경·취소 제안이 아닐 것
- 내 역할과 관련 있을 것

내부 점수는 0~1이지만 규칙으로 매긴 값이라 확률처럼 보이면 안 된다.
화면에는 **높음 / 검토 필요 / 낮음** 세 단계로만 표시한다.
자동등록되지 않은 후보에는 이유를 그대로 적어 보여준다 (`autoRegisterBlockers`).
