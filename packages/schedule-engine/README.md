# @cool-lin/schedule-engine

쿨메신저 내보내기(`.xls`)를 읽어 **일정 후보**로 바꾸는 규칙 엔진.
해커톤 역할 분담 중 **3번 «엑셀 데이터 학습 및 규칙 도출»** 의 산출물이다.

- 1번(자동 다운로드·로컬 AI 연동)과 2번(위젯)은 이 패키지를 **읽기만** 한다.
- 이 패키지는 파일을 읽고 후보를 계산할 뿐, 화면을 그리거나 파일을 내려받지 않는다.

```bash
npm install
npm run analyze    # 실제 파일을 훑어 표현 빈도 통계 → 규칙 도출 근거
npm run extract    # 실제 파일에서 일정 후보 뽑기
npm run trace      # 한 문장이 어떻게 후보가 되는지 단계별로 보기
npm run sample     # 위젯 연동용 출력 견본 만들기 (개인정보 없음)
npm run eval       # 합성 golden set 회귀 평가
npm test           # 단위 테스트
```

문서
- **[RULES.md](./RULES.md)** — 쪽지에서 무엇을 보고 할 일을 뽑는지 (규칙 전체)
- **[EVALUATION.md](./EVALUATION.md)** — 평가 지표의 분모와 제외 기준
- 이 문서 — 연동 방법과 JSON 계약

---

## 1. 무엇을 하는가

```
쿨메신저 .xls
  → 형식 판별 (첫 바이트)      OLE2 BIFF / SpreadsheetML 2003 XML 둘 다
  → 헤더 이름으로 열 찾기       위치가 아니라 이름으로
  → 본문 정규화                CRLF·제어문자·bidi 정리
  → 인용문 분리                "OOO님이 보낸글 >>" 이후는 판단에서 제외
  → 중복 제거                  HMAC 지문 (마스킹 «전» 원문 기준)
  → 민감정보 탐지·마스킹        주민번호·계좌·비밀번호·상담 → 격리
  → 문장 나누기
  → 날짜·시각·교시 추출         ★ 발송일을 기준으로 «내일»·«금요일까지»를 절대 날짜로
  → 문장 단위 분류·점수
  → 관계 판정 (변경·취소)
  → 일정 후보
```

핵심은 **기준 시각이 «쪽지 발송일»** 이라는 점이다. 「모레까지」라고 적힌 쪽지를
8월 27일에 받았으면 8월 29일이고, 8월 31일에 받았으면 9월 2일이다.

## 2. 위젯(역할 2)에 넘기는 계약

`Candidate` 배열 하나가 전부다. 위젯은 이 JSON만 알면 된다.

**견본 파일이 이미 저장소에 있다.** 실제 엑셀 없이도 위젯을 붙여 볼 수 있다.

```
fixtures/sample-output.json   # 합성 데이터로 만든 후보 20건. 개인정보 없음
```

실제 파일에서 뽑으려면:

```bash
npm run extract -- --today=2026-08-28 --json=candidates.json
```

⚠ 실제 파일로 만든 JSON에는 학생·학부모 실명이 들어갈 수 있다. **커밋하지 않는다.**

```ts
interface Candidate {
  id: string;
  proposedTitle: string;        // 캘린더에 넣을 제목
  candidateType:                // 분류
    | "OFFICIAL_EVENT"          //   공식 행사·회의·연수
    | "PERSONAL_TASK"           //   내가 할 일
    | "DEADLINE"                //   기한이 있는 제출·신청
    | "OPTIONAL_EVENT"          //   희망자 대상 → 반드시 사용자 확인
    | "REFERENCE_NOTICE"        //   참고 공지
    | "URGENT_NOTICE";          //   당일 긴급 → 캘린더보다 알림

  startAt: string | null;       // "2026-08-28T15:20" 또는 "2026-08-28"
  endAt:   string | null;
  dueAt:   string | null;       // 마감은 startAt 이 아니라 여기에 들어간다
  timePrecision: "date_only" | "period" | "exact";
  periodStart: number | null;   // 교시. 교시표가 없으면 시각으로 바꾸지 않는다
  periodEnd:   number | null;

  location:   string | null;    // "강당"
  actionText: string | null;    // "제출"
  targetText: string | null;    // "전 교직원", "2학년"
  keywords:   string[];         // 캘린더에 넣을 핵심 일정 단어

  reasoning: string[];          // 화면에 그대로 보여줄 수 있는 판단 근거
  confidence: number;           // 0~1
  confidenceBand: "높음" | "검토 필요" | "낮음";
  relationType: "new" | "update" | "cancel" | "recurrence";
  ambiguityFlags: string[];     // 하나라도 있으면 자동등록하지 않는다

  sourceGroupId: string;        // 같은 쪽지에서 나온 후보를 묶는 값
  messageSentAt: string;        // 출처 쪽지 발송일
  counterpart: string;

  autoRegisterEligible: boolean; // 자동등록 안전 조건을 모두 통과했는가
  autoRegisterBlockers: string[]; // 통과하지 못한 이유
}
```

### 위젯이 지켜야 할 것

- **시간대 접미사가 없다.** `startAt`은 `Asia/Seoul` 벽시계 값이다. `new Date(startAt)`으로
  파싱하면 브라우저 시간대에 따라 날이 밀린다. 문자열 그대로 쓰거나 명시적으로 다뤄야 한다.
- `timePrecision`이 `date_only`나 `period`면 **시각이 없는 것이다.** 00:00으로 표시하지 않는다.
  교시는 `5~6교시 · 시간 미설정`처럼 보여준다.
- `ambiguityFlags`가 비어 있지 않으면 사용자 확인 없이 등록하지 않는다.
- `proposedTitle`·`counterpart`는 **믿을 수 없는 평문**이다. HTML로 렌더링하거나
  `dangerouslySetInnerHTML`에 넣지 않는다 (PRD 6장).
- `autoRegisterEligible === false`면 `autoRegisterBlockers`를 사용자에게 그대로 보여준다.

## 3. 왜 이렇게 만들었는가 — 실제 데이터에서 도출한 규칙

`npm run analyze` 로 실제 쪽지 3,236건(중복 제거 후)을 세어 얻은 결과다.
숫자는 «그 표현이 나온 쪽지의 비율»이다.

| 발견 | 수치 | 규칙에 반영한 방식 |
|---|---|---|
| **요일만 적힌 마감이 «모레»보다 70배 흔하다** | 요일만 6.9% vs 모레 0.1% | `금요일까지`를 발송일 이후 가장 가까운 금요일로 해석하고 `요일만 적힘` 표시를 붙인다 |
| 날짜 표현이 아예 없는 쪽지가 절반 이상 | 57.7% | 날짜가 없으면 분류 이전에 후보에서 뺀다. 가장 싼 관문이다 |
| 제목 열은 대개 본문 첫 줄이 잘린 값 | 본문과 일치 71.2%, 24자 이상 87.5%, 인사말 시작 22.2% | 제목을 그대로 쓰지 않고 「무엇을 + 무엇 한다」로 다시 만든다 |
| 교시 표현이 매우 흔하다 | 6.8% (총 827회) | 교시를 시각으로 추정하지 않고 번호를 보존한다. 교시표가 없으면 `교시표 미설정` |
| `부탁드립니다` 23.4%, `감사합니다` 30.2% | 공지·잡담 양쪽에 다 붙는다 | **단독 신호로 쓰지 않는다.** 가중치를 낮추고 다른 근거와 함께만 쓴다 |
| 취소·연기는 매우 드물다 | 취소 0.3%, 연기 0.1% | 드물어도 틀리면 치명적이라 별도 관계 판정으로 다룬다 |
| 계좌번호 정규식이 날짜·전화번호를 오탐 | `2026-08-24`가 걸림 | 자릿수·앞자리·주변 날짜 문맥으로 걸러낸다 |
| 발신자 직책이 괄호 안에 들어 있다 | `최은지(교무부장,107)` | 역할 태그와 맞춰 «대상적합» 점수에 쓴다 |

### 날짜 해석 규칙

| 표현 | 해석 | 모호 표시 |
|---|---|---|
| `8월 28일`, `8/28`, `2026-08-28`, `9.2.` | 그대로 | 해가 바뀌면 `연도 생략` |
| `오늘`·`금일` / `내일`·`명일` / `모레` / `글피` | 발송일 +0 / +1 / +2 / +3 | — |
| `이번 주 화요일`, `다음 주 월요일` | 발송일이 속한 주 기준 | — |
| **`금요일까지`** (요일만) | **발송일 이후 가장 가까운 그 요일** | **`요일만 적힘`** |
| `8월 27일 목요일` (일치) | 날짜를 쓰고 요일은 검증만 | — |
| `8월 27일 금요일` (불일치) | 자동등록하지 않음 | `날짜·요일 불일치` |
| `5~6교시` | 교시표가 있을 때만 시각으로 | 없으면 `교시표 미설정` |
| `8/11~8/13` | 시작·종료 | 종료 불명확하면 `종료일 불명확` |
| `오후 3시 30분` | 정확한 시각 | 오전·오후 없이 1~7시면 `오전·오후 불명확` |

### 신뢰도 점수 (기술계획서 7.2 공식 그대로)

```
점수 = 날짜정밀도 + 행동/행사 + 대상적합 + 0.08
       - (지난 날짜면 0.25)
       - (선택 참여 표현이면 0.15)
       - 0.12 × 모호표시 개수
```

화면에는 숫자를 보여주지 않는다. `높음 ≥ 0.90` / `검토 필요 0.60~0.89` / `낮음 < 0.60`
세 단계만 보여준다.

## 4. 파일 형식에 대한 함정

쿨메신저가 `.xls`로 내보낸 파일은 **확장자가 같아도 내부 형식이 두 가지**다.
실제 샘플에서 둘 다 나왔다.

| 첫 바이트 | 실제 형식 | 읽는 방법 |
|---|---|---|
| `D0 CF 11 E0 …` | OLE2 (구형 진짜 xls) | SheetJS |
| `EF BB BF 3C 3F 78 6D 6C` | SpreadsheetML 2003 XML | **직접 파싱** (`src/adapters/spreadsheetml.ts`) |
| `50 4B 03 04` | ZIP (xlsx) | SheetJS |

SpreadsheetML 파서에서 특히 조심한 것:

- `ss:Index`를 존중한다. 무시하면 열이 밀려 **제목 자리에 날짜가 들어간다**
- 스스로 닫는 `<Cell/>`은 종료 이벤트가 오지 않으므로 따로 처리한다
- 네임스페이스 접두어를 떼고 이름을 비교한다 (`ss:Name` == `Name`)
- 한도를 넘으면 부분 결과를 쓰지 않고 오류를 낸다

## 5. 알려진 한계

- **Recall을 재지 못한다.** 「진짜 일정이 몇 개였는지」에 대한 사람 라벨이 없다.
  `EVALUATION.md` 5장 참고.
- **제목이 짧을 때가 있다** (`제출`, `참석`). 목적어가 다른 문장에 있으면 못 찾는다.
  틀린 긴 제목보다 짧고 맞는 제목을 택했다.
- **`실시/진행`류 서술어에 기대는 부분**이 있어, 행사 이름이 사전에 없고 서술어도 없으면
  `REFERENCE_NOTICE`로 떨어진다.
- **PRD·기술계획서는 Rust(`calamine`) + Tauri를 전제한다.** 이 패키지는 TypeScript다.
  규칙·사전·평가 기준은 그대로 옮길 수 있게 데이터로 분리해 두었다
  (`src/classify/lexicon.ts`, `fixtures/golden.json`).
